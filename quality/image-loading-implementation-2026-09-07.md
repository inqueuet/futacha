# 画像表示遅延の改善実施記録

2026-09-07。基準: `3c3146d9b6fffb58103cbb0f537272fd680bb5c3`。
承認された[改善案と副作用レビュー](image-loading-improvement-plan-2026-09-07.md)を実装する。

## 実施計画と変更

1. **通信と再試行**: Androidにアプリ所有の画像専用OkHttpを追加し、古い接続からの復旧を有効化。一般通信は従来どおり。画像クライアントは各リダイレクトを含めGET/HEADの静的メディアURLを検査し、投稿や`sd.php`等を拒否する。Cookie保存先は既存と共有し、リダイレクトはKtorで処理する。
2. **再試行の重複解消**: Coilのネットワーク取得全体で初回＋最大2回に統一。Ktorの画像用再試行とUIの追加再試行を止める。レスポンスヘッダーだけでなく本文受信中の切断も同じ予算で処理する。500/502/503/504と回復可能な接続例外だけを対象にし、キャンセル・TLS検証・認証・429は反復しない。バックオフは1秒/2秒＋ジッター。
3. **フォールバックとキャッシュ**: 別拡張子探索およびサムネイルから元画像へのエラー時切替は404/410に限定。途中の候補が通信障害ならそこで止める。4xx/5xxの保存を禁止し、保存済みエラーも再検証する。正常キャッシュの形式・保存領域を維持する。
4. **先読みの寿命**: ビューアーごとの管理対象を隣接最大2件、アプリ全体の先読み実行を1件に制限。不要になった取得はキャンセルし、同じURLを表示中の利用者がいる場合は完了まで維持する。Coilによる同一URL取得調整を継続する。
5. **明示的な再読込**: 操作トークンごとの最初の成功までは古いキャッシュを避け、成功結果は保存する。その後の再表示は通常のキャッシュ利用に戻す。ローダーがメモリのみからディスク利用へ移行しても操作記録を引き継ぐ。
6. **iOS待機時間**: Darwinの一律75秒の後段上書きを除去し、画像用ソケット15秒設定を有効にする。一般通信は明示的に75秒へ設定し、従来の実効値を維持する。

## 副作用への対応と限界

- 実際の失敗は表示し、ユーザーによる再読込を残す。404/410では従来の元画像・拡張子補正を維持する。デコード失敗を根拠に別URLへ切り替える動作は止めるため、壊れた画像と正しい別形式が併存する特殊ケースは自動補正されない。
- 静的メディア拡張子を持たない外部URL、スクリプト経由の配信は画像専用通信で拒否する。既存パーサー／ビューアーが扱うメディア拡張子、署名付きクエリ、空白を含むURLは許可する。
- Androidは一般通信と画像通信の接続プールを分けるため、アプリ全体で同時に保持する接続数は増え得る。画像のデコード並列数・キャッシュ容量は今回増やしていない。
- 先読みの抑制により、未取得画像へ連続スワイプした際は読み込みを待つ場合がある。通常の表示要求に同じ1件制限は掛けない。
- 最大3回はCoil側の論理的な試行数。OkHttp内部復旧・リダイレクト・別の表示要求を含む全HTTP送信数の絶対上限ではない。90秒設定も操作全体の絶対上限ではない。
- 旧404キャッシュを再検証するため、消えた画像の再表示では従来より通信が増える場合がある。全キャッシュ消去は行わない。
- 品質ゲートで検出された既存の通知権限ランチャーについて、画面モード世代を検査する既存共通ラッパーへ接続した。画像最適化とは独立した最小修正。

iOSの画像通信4件は、ソケットタイムアウトの上書き防止（1秒設定で1,018ms）、503が元URLへの3要求で終了すること、本文受信途中の切断から2要求で成功すること、旧404キャッシュを再検証して正常画像をディスクから再利用できることを確認。JVMでは本文切断→503が混在しても合計3試行で終了する。先読みの実行上限と表示中取得の保護、明示再読込後のキャッシュ利用もテストした。

### iOS画面と実機の残条件

既存シミュレータでは更新履歴の保存状態、新規シミュレータで複数モードのテストを連続実行すると先行テストの初期データが影響し、初期板画面のアサーションに失敗した。元のシミュレータのデータは消していない。検証専用SE3 (`0B9DAFAB-4095-4F0F-B867-868F4570B6FC`) を作成し、初期状態を分けて再確認した。

- 新規シミュレータの通常モード: 板→カタログ→スレッド→投稿フォーム→添付一覧のUIテスト合格。
- 互換モードの先読み設定選択: UIテスト合格。
- 互換モードの検索・ギャラリー: 独立した初期状態で、スレッド検索→ギャラリー→画像ビューアー→長押しメニューまで通過。保存部分の既存テストは製品の「一括保存／選択を終了」に対して旧名称「保存モード」を探していた。基準HEADでも同じ不一致があることを確認し、テストを現在の選択件数表示と終了操作へ修正し、検索・ギャラリー・ビューアー・長押し・一括保存の選択開始／終了・スレッドへ戻る全経路が合格した（33.089秒）。

**iPhone実機への改善版インストールは未完了**。キーチェーン `User interaction is not allowed` / codesign `errSecInternalComponent` により署名で停止し、Mac側の解除を依頼済み。iOS Native・シミュレータの成功をiPhone実機での成功とは扱わない。長時間・低速回線での実機成功率や電池使用量の比較も今回の固定回帰試験には含まない。
